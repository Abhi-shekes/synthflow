# Contributing to SynthFlow

Thanks for your interest — the project is early, so the most useful contributions
right now are different from what they'll be once the core lands.

## Right now (pre-Phase 1 code)

- Read [ROADMAP.md](ROADMAP.md) and [TODO.md](TODO.md) first.
- Open an issue before starting significant work, so effort isn't duplicated.
- Design/architecture feedback on the roadmap is welcome via issues or discussions.

## Once the core exists

- Fork the repo, branch off `main`.
- Keep PRs scoped to one change; large multi-part PRs are hard to review.
- Match the existing code style (linters/formatters will be enforced by CI once set up).
- Add or update tests for anything behavior-changing.
- Reference the relevant ROADMAP/TODO item in your PR description.

## Plugin contributions

SynthFlow is designed to be extended via output plugins, rule plugins, and generator
plugins (see ROADMAP.md Phase 5). Once the plugin interface is documented, community
plugins are one of the highest-value ways to contribute without touching core.

## Code of conduct

Be respectful and constructive. Disagreements about design are fine and expected;
personal attacks are not.
